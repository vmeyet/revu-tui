# 05 · AI in context

Two providers, two jobs, one trait.

| Provider | Job | Shape |
|---|---|---|
| TypeSafe Jev (`ai/typesafe.rs`, copied from slack-tui) | triage: cheap typed judgments over many items | `Question::{Noul, Choice, Score}` → probabilities |
| Anthropic Claude (`ai/anthropic.rs`) | conversation: explain, summarise, draft, find risks | streamed markdown |

Both are behind `[ai] enabled = true`, see `04-security.md` for keys and what is sent.

## Triage with Jev

Runs in the background on the queue and on an open MR, results decorate the UI, never block it.
Every failure is `Unavailable` and the UI falls back to no decoration, exactly as slack-tui's inbox.

Questions, asked once per `(mr, head_sha)` and cached:

| Id | Question | Used for |
|---|---|---|
| `urgency` | Score over `["can wait", "this week", "today", "blocking someone"]` from title, description, age, pipeline, labels, unresolved count | queue sort inside a section, `!` badge on the top level |
| `size` | Choice `trivial / focused / large / sprawling` from file list and diff stats | `~` badge on `sprawling`, and the "start with" hint |
| `waits_on_me` | Noul: "is the last activity a question or change request addressed to the reviewer?" from the last three notes | `◆` pulsing in the queue row |
| `risk` per file | Score over `["cosmetic", "logic", "data or schema", "security or auth"]` from path and hunks | file tree colour tint, default fold for `cosmetic` when the MR is `sprawling` |

Jev is asked with the same `state` JSON the TUI holds, no prose prompt.
`PARALLEL_REQUESTS = 8` and the retry table are kept from slack-tui.

## Conversation with Claude

Raw HTTPS to `POST https://api.anthropic.com/v1/messages`, no SDK exists for Rust.
Headers: `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`.

Request shape:

```json
{
  "model": "claude-opus-5",
  "max_tokens": 16000,
  "stream": true,
  "system": [
    { "type": "text", "text": "<role and rules>" },
    { "type": "text", "text": "<MR title, description, file list>", "cache_control": { "type": "ephemeral" } },
    { "type": "text", "text": "<selected file diff or hunk with context>", "cache_control": { "type": "ephemeral" } }
  ],
  "messages": [ { "role": "user", "content": "<question>" } ]
}
```

- Model from `[ai] model`, default `claude-opus-5`. Thinking is adaptive by default on this model, so the `thinking` field is omitted.
- Streaming always: the answer paints token by token in the right pane. Parse SSE `content_block_delta` events with `delta.type == "text_delta"`; stop on `message_stop`; on `stop_reason == "refusal"` show the `stop_details.explanation` line instead of an answer.
- Prompt caching: the MR block and the file block carry `cache_control`, so the second question on the same file costs a fraction. The question is last, after the last breakpoint. Verify with `usage.cache_read_input_tokens` in a debug log line.
- Follow-ups continue the same `messages` array within the session; a new file or MR starts a new conversation.
- Errors: 401 → toast `anthropic key rejected`; 429 and 5xx → one retry after `retry-after`; anything else → the message from `error.message`.

System prompt, short and stable (it is cached):

```
You help a code reviewer reading a GitLab merge request in a terminal.
Answer in plain markdown, short paragraphs, code in fences. Refer to lines as `path:new_line`.
When asked for a comment, write it as the reviewer would post it: direct, specific, no greeting.
Say when the diff alone cannot answer.
```

## Context builder (`ai/mod.rs`)

```rust
pub struct Scope { Mr, File(path), Hunk(path, index), Thread(id), Lines(path, Range<u32>) }

pub fn context(review: &Review, scope: Scope, budget: usize) -> Context
```

- Always: title, description (trimmed to 2000 chars), file list with `+/-` counts, pipeline status.
- `File`: the full diff of that file, up to `budget` chars; beyond it, hunks are kept whole from the top and a line says how many were cut.
- `Hunk` and `Lines`: the hunk plus 20 lines of surrounding diff.
- `Thread`: the anchored hunk plus every note as `author: body`.
- Budget default 60 000 chars. The builder never cuts a hunk in the middle.

## Prompts offered (`a` then a letter, or `:ask <text>`)

| Key | Scope | Question sent |
|---|---|---|
| `a e` | hunk or file | "Explain what this change does and why it might be here." |
| `a r` | file | "List the risks and the things a careful reviewer should check. Be concrete." |
| `a s` | MR | "Summarise this MR in five lines and suggest the reading order of the files." |
| `a t` | thread | "Summarise this thread and say what is still open and who it waits on." |
| `a c` | lines | "Draft a review comment for these lines about: <prompt for the concern>" |
| `a a` | any | free question typed in the input row |

An answer in the right pane offers: `c` turn it into a draft on the same anchor (editable first), `y` copy, `enter` follow-up question, `esc` close.

## Cache

`ai/<project_id>/<iid>/<head_sha>/<sha1(scope + question)>.json` holds the full answer.
Cache hits paint instantly with a `cached` tag in the pane title; `R` in the pane re-asks.
