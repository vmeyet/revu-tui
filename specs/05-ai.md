# 05 · AI in context

Two providers, two jobs, one trait.

| Provider | Job | Shape |
|---|---|---|
| TypeSafe Jev (`ai/typesafe.rs`, copied from slack-tui) | triage: cheap typed judgments over many items | `Question::{Noul, Choice, Score}` → probabilities |
| Anthropic Claude (`ai/anthropic.rs`) | conversation: explain, summarise, draft, find risks | streamed markdown |

Each is behind its own switch, `[ai.anthropic] enabled = true` and `[ai.typesafe] enabled = true`; keys are keychain secrets set with `revu ai login <provider>`, see `04-security.md` for keys and what is sent.

## Triage with Jev

Runs in the background on the queue and on an open MR, results decorate the UI, never block it.
Every failure is `Unavailable` and the UI falls back to no decoration, exactly as slack-tui's inbox.

Questions, asked once per `(mr, head_sha)` and cached:

| Id | Question | Used for |
|---|---|---|
| `urgency` | Score over `["can wait", "this week", "today", "blocking someone"]` from title, description, age, pipeline, labels, unresolved count | queue sort inside a section, `!` badge on the top level |
| `size` | Choice `trivial / focused / large / sprawling` from file list and diff stats | `~` badge on `sprawling`, and the "start with" hint |
| `waits_on_me` | Noul: "is the last activity a question or change request addressed to the reviewer?" from the last three notes | `◆` pulsing in the queue row |
| `risk` per file | Score over `["cosmetic", "logic", "data or schema", "security or auth"]` from path and hunks | file tree colour tint, default fold for `cosmetic` when the MR is `sprawling` |

Jev is asked with the same `state` JSON the TUI holds, no prose prompt.
Implementation notes (M4):
- A queue verdict is cached per MR and bound to the `updated_at` Jev saw: the queue list has no head commit, and any push or note moves `updated_at`, so a moved MR is asked again.
- `waits_on_me` needs the notes, which the queue does not carry, so it is asked when the MR is opened, with the per-file risks, cached per head commit; the queue shows `◆` once that reading exists.
- `!` marks an urgency of 2.5 or more (halfway into "blocking someone"); `waits_on_me` needs a probability of 0.6.
- The default fold for `cosmetic` files in a `sprawling` MR is not done: folds moving under the reader after an answer lands would surprise more than help.
`PARALLEL_REQUESTS = 8` and the retry table are kept from slack-tui.

## Conversation with Claude

Raw HTTPS to `POST https://api.anthropic.com/v1/messages`, no SDK exists for Rust.
Headers: `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`.

Request shape:

```json
{
  "model": "claude-opus-5",
  "max_tokens": 16000,
  "stream": true,
  "system": [
    { "type": "text", "text": "<role and rules>" },
    { "type": "text", "text": "<MR title, description, file list>", "cache_control": { "type": "ephemeral" } },
    { "type": "text", "text": "<selected file diff or hunk with context>", "cache_control": { "type": "ephemeral" } }
  ],
  "messages": [ { "role": "user", "content": "<question>" } ]
}
```

- `revu ai ask <mr> [--file PATH [--lines 13-20]] [question]` sends the same request from the shell and streams the answer to stdout; the last line (stderr) names the model and the input, cached and output tokens.
- On the Opus 5 and Fable 5 families the request carries `"fallbacks": "default"` with the `anthropic-beta: server-side-fallback-2026-07-01` header, so a question a classifier declines is answered by Anthropic's recommended fallback model; a `fallback` content block in the stream voids the partial text before it. Other models stop on the refusal.
- Model from `[ai.anthropic] model`, default `claude-opus-5`. Thinking is adaptive by default on this model, so the `thinking` field is omitted.
- Streaming always: the answer paints token by token in the right pane. Parse SSE `content_block_delta` events with `delta.type == "text_delta"`; stop on `message_stop`; on `stop_reason == "refusal"` show the `stop_details.explanation` line instead of an answer.
- Prompt caching: the MR block and the file block carry `cache_control`, so the second question on the same file costs a fraction. The question is last, after the last breakpoint. Verify with `usage.cache_read_input_tokens` in a debug log line.
- Follow-ups continue the same `messages` array within the session; a new file or MR starts a new conversation.
- Errors: 401 → toast `anthropic key rejected`; 429 and 5xx → one retry after `retry-after`; anything else → the message from `error.message`.

System prompt, short and stable (it is cached), in `src/ai/context.rs`:

```
You help a developer review a merge request in a narrow terminal pane.
Be brief: lead with the answer, no preamble, no closing summary, no headers.
Use simple words and short sentences, one idea each. Plain markdown only.
Point at code as `path:line`. Quote code only when it helps, in a fence.
Say what you are unsure of in one sentence; if the diff cannot answer, say so and stop.
```

Every question fixes its shape and length: the pane is narrow and the reader is mid-review.

## Context builder (`ai/mod.rs`)

```rust
pub struct Scope { Mr, File(path), Hunk(path, index), Thread(id), Lines(path, Range<u32>) }

pub fn context(review: &Review, scope: Scope, budget: usize) -> Context
```

- Always: title, description (trimmed to 2000 chars), file list with `+/-` counts, pipeline status.
- `File`: the full diff of that file, up to `budget` chars; beyond it, hunks are kept whole from the top and a line says how many were cut.
- `Hunk` and `Lines`: the hunk plus 20 lines of surrounding diff.
- `Thread`: the anchored hunk plus every note as `author: body`.
- Budget default 60 000 chars. The builder never cuts a hunk in the middle.

## Prompts offered (`a` then a letter, or `:ask <text>`)

| Key | Scope | Question sent |
|---|---|---|
| `a e` | hunk or file | "What does this change do, and why? Answer in 2 or 3 sentences." |
| `a r` | file | "What could break? List at most 5 real risks, worst first, one line each: `path:line`: the risk. Skip style, naming and anything the tests clearly cover. If there is no real risk, say only: No real risk." |
| `a s` | MR | "Summarise this MR in at most 5 bullets: what changes and why. Then one line: the order to read the files in." |
| `a t` | thread | "In at most 3 bullets: what is agreed, what is still open, and who must act next." |
| `a c` | lines | "Write the review comment for these lines about: <concern>. Write it as the reviewer would post it: 1 to 3 sentences, direct, no greeting. Give the fix when it is clear." |
| `a a` | any | free question typed in the input row |

An answer in the right pane offers: `c` turn it into a draft on the same anchor (editable first), `y` copy, `enter` follow-up question, `R` ask again past the cache, `esc` close.

Implementation notes (M4):
- `a e` and `a a` are about the hunk under the cursor (its file on a file row, the MR elsewhere); `a r` the cursor's file; `a c` the selected lines (or the cursor line), with the concern typed in the compose box of the answer pane.
- `c` turns an answer into a draft on the lines asked about, or into a reply for `a t`; an answer about the whole MR or a file has no line, and says so.
- The answer takes the right pane; opening a thread or the file tree gives the pane back to them, and a new MR drops the answer.
- The cache key is a hash of the whole request body (model, system blocks, every turn), so an answer is reused only for the same question on the same diff, follow-ups included; a cut or refused answer is not cached.
- The first question of a session toasts the provider and model, and says the MR goes to Anthropic.

## Cache

`ai/<project_id>/<iid>/<head_sha>/<sha1(scope + question)>.json` holds the full answer.
Cache hits paint instantly with a `cached` tag in the pane title; `R` in the pane re-asks.
